## 3. Dataset inspection

The original synthetic CSV has header `Case_ID,Activity,Timestamp,Resource`, 5000 events, 1000 distinct cases and five activities in the same order for every case. It has no start, queue-entry or lifecycle observations; its timestamp timezone is not specified. Resource strings are generated from activity prefixes, not proof of actual capacity. Treat this as a synthetic gap benchmark, not a ground-truth queue/capacity benchmark.

Independent arithmetic over adjacent recorded timestamps within each case (not a confirmed production mapping) yields:

| Transition | Observations | Mean gap (s) | Min (s) | Max (s) |
| --- | ---: | ---: | ---: | ---: |
| Cutting → CNC_Milling | 1000 | 1816.98 | 900 | 2700 |
| CNC_Milling → Welding | 1000 | 14395.44 | 10800 | 18000 |
| Welding → Surface_Coating | 1000 | 1811.94 | 900 | 2700 |
| Surface_Coating → Quality_Check | 1000 | 1792.26 | 900 | 2700 |

The high Welding-associated gap is injected by the generator. It is not queue waiting, service duration, resource utilization or a causal capacity diagnosis. The mock API's CNC ranking is independent of this dataset. The result is a numerical reference only; TASK-03 requires confirmed timestamp semantics before application analysis.
